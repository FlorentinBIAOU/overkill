need:

  en: "Find the right page in an internal corpus — a handbook, a knowledge base, documentation — from what a reader types into a search box."

scenario:
  fr: "On voit monter une base vectorielle et une chaîne d’embeddings pour un fonds de quelques centaines de pages, avant même d’avoir allumé l’index plein texte de la base de données qui porte déjà ces pages. SQLite a FTS5, PostgreSQL a tsvector, MySQL a FULLTEXT : l’index inversé et le classement BM25 sont là, mis à jour dans la même transaction que le document et sauvegardés avec lui. La question n’est pas de savoir si la recherche par le sens existe, c’est de savoir combien de vos requêtes en ont besoin — et vos journaux de recherche le disent."
  en: "A vector database and an embedding pipeline get stood up for a corpus of a few hundred pages, before anyone has switched on the full-text index of the database already holding those pages. SQLite ships FTS5, PostgreSQL has tsvector, MySQL has FULLTEXT: the inverted index and the BM25 ranking are right there, updated in the same transaction as the document and backed up with it. The question is not whether search by meaning exists, it is how many of your queries need it — and your search logs answer that."

verdict_rationale:
  fr: "N0 gagne parce que l’index est déjà là : il se met à jour dans la même transaction que le document, se sauvegarde avec lui, et ne coûte aucun service à exploiter. Il a surtout la propriété qu’on attend d’une barre de recherche et que N2 abandonne : quand il n’a rien, il le dit. N1 n’est pas plus lent, et ce qu’il coûte de plus est un index à reconstruire hors de la base : c’est le même algorithme avec les molettes sorties — prenez-le le jour où vous devez changer le tokenizer ou la règle d’appariement, pas pour obtenir un meilleur défaut."
  en: "N0 wins because the index is already there: it updates in the same transaction as the document, is backed up with it, and costs no service to operate. More to the point, it has the property a search box needs and N2 gives up: when it has nothing, it says so. N1 is no slower, and what it costs extra is an index to rebuild outside the database: it is the same algorithm with the dials exposed — reach for it the day you have to change the tokenizer or the matching rule, not to get a better default."
