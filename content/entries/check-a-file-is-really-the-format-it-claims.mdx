scenario:
  fr: "On voit des formulaires de téléversement se fier à l’extension du nom de fichier, ou à l’en-tête Content-Type, pour décider si une pièce jointe est une image ; et on voit désormais envoyer le fichier à un modèle pour qu’il le dise. Les deux premiers sont écrits par le client, donc par l’attaquant quand il y en a un ; le troisième fait sortir un fichier non contrôlé de votre infrastructure pour obtenir une réponse que ses seize premiers octets donnent déjà. La signature d’un format est une table publiée, et la lire est une comparaison."
  en: "Upload forms are routinely seen trusting the file name’s extension, or the Content-Type header, to decide whether an attachment is an image; and now they are seen sending the file to a model so it can say. The first two are written by the client, which means by the attacker when there is one; the third takes an unvetted file out of your infrastructure to get an answer its first sixteen bytes already give. A format’s signature is a published table, and reading it is a comparison."

      en: "There is no level above this one for that question. The day what you want to know stops being “which format” and becomes “what is inside it” — a macro, a script in an SVG, a payload —, that is malware scanning or a sandbox, not reading a signature."

  - level: N1

      fr: "Il existe bien une technique classique pour cela — classer un fragment de fichier sur des statistiques d’octets, employée en analyse post-mortem quand il n’y a plus d’en-tête —, et elle est exactement ce qu’un contrôle de téléversement ne doit pas faire : elle rend un type probable là où la question appelle une réponse vérifiable. Sur un fichier qui porte sa signature, elle n’ajoute rien ; sur un fichier qui n’en porte pas, elle remplacerait un refus explicite par une supposition."
      en: "There is a classic technique for this — classifying a file fragment from byte statistics, used in forensics when no header is left — and it is exactly what an upload check must not do: it returns a probable type where the question calls for a verifiable answer. On a file that carries its signature it adds nothing; on a file that does not, it would replace an explicit refusal with a guess."

      en: "This level disqualifies itself by what it asks you to do with the file: send it to a third party. verdict_rationale:
  fr: "N0, parce que la question a une réponse exacte dans les premiers octets et que l’enjeu est de savoir d’où vient la réponse : le nom du fichier et l’en-tête Content-Type sont écrits par le client, le rapport les traite comme une affirmation à contredire et pas comme une donnée. Le code va une ligne plus loin que les bibliothèques quand il le faut : `file-type` ouvre une archive ZIP pour distinguer un .docx d’un .xlsx, `puremagic` ne le fait pas, et douze lignes de `zipfile` alignent le Python sur le JavaScript. Ce que ce niveau ne sait pas faire est dit plutôt que deviné — les formats texte reviennent non reconnus, et un fichier non reconnu n’est jamais autorisé."
  en: "N0, because the question has an exact answer in the first bytes and what matters is where the answer comes from: the file name and the Content-Type header are written by the client, and the report treats them as a claim to be contradicted rather than as data. The code goes one line further than the libraries where it must: file-type opens a ZIP archive to tell a .docx from a .xlsx, puremagic does not, and twelve lines of zipfile bring the Python side in line with the JavaScript one. What this level cannot do is stated rather than guessed — text formats come back unrecognised, and an unrecognised file is never allowed."
