need:
  fr: "Obtenir le nom, la référence, la marque, le prix et la disponibilité d’un article depuis la page qui le présente."
  en: "Get the name, reference, brand, price and availability of an item from the page that shows it."

scenario:
  fr: "On voit envoyer le source entier d’une fiche produit à un modèle généraliste pour qu’il en tire un nom et un prix, ou écrire des sélecteurs qu’une refonte casse. Presque toutes les boutiques publient pourtant ces valeurs en clair, quelques lignes plus haut dans la même page, dans un bloc JSON-LD que les moteurs de recherche leur demandent d’émettre. Aller les chercher dans le rendu quand elles sont déclarées dans l’en-tête est le cas de sur-ingénierie le mieux documenté de l’extraction web."
  en: "Sending the whole source of a product page to a general-purpose model to pull out a name and a price is a common sight, as is writing selectors that the next redesign breaks. Yet almost every shop publishes those values in plain text, a few lines higher in the same page, inside a JSON-LD block that search engines ask them to emit. Going to look for them in the rendering when they are declared in the head is the best-documented piece of over-engineering in web scraping."

verdict_rationale:
  fr: "N0, parce que la donnée est déjà là : la boutique l’écrit pour les moteurs de recherche, typée et nommée par schema.org, et la lire est un appel à l’analyseur JSON de votre langage. Le code n’est intéressant que par ce qu’il refuse de trancher — plusieurs produits sur la même page, un prix écrit « 1 234,56 » qui n’est pas un nombre — et par un détail de production : le balayage des blocs est écrit à la main parce qu’une expression régulière sur une page qu’on n’a pas écrite s’effondre, vingt mille balises ouvertes suffisant à la faire dépasser dix secondes. Montez à N3 pour la boutique qui n’émet rien, en sachant que la garde qui y rend l’appel défendable — écarter toute valeur absente de la page — écarte aussi des valeurs justes."
  en: "N0, because the data is already there: the shop writes it for search engines, typed and named by schema.org, and reading it is a call to your language’s JSON parser. The code is only interesting for what it refuses to settle — several products on one page, a price written “1 234,56” that is not a number — and for one production detail: the block scan is written by hand because a regular expression over a page you did not write collapses, twenty thousand unclosed tags being enough to push it past ten seconds. Move up to N3 for the shop that emits nothing, knowing that the guard that makes the call defensible there — dropping any value absent from the page — drops correct values too."
